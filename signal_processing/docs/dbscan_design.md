## 1. 전제와 확인된 사실

### 센서 (RETINA-4SN)

- TI AWR2243 (3TX × 4RX) × 4 캐스케이드, 12TX × 16RX = 192 가상 안테나, 77~81 GHz 대역 (교육 자료 12쪽)
- 프레임당 최대 5000점
- 출력: 점마다 `x, y, z, doppler, power, target_id`. **격자 칸 번호는 주지 않는다.**
- 교육 자료 12쪽의 시야각 90°, 각도 해상도 수평·수직 3.8°는 **"RETINA-4S"(패치 안테나 1개) 항목**에 적혀 있다. 192 가상 안테나 배열인 4SN의 해상도는 별도 확인이 필요하다.

### 격자 칸 번호 (현재 구현)

`src/preprocessing/polar_grid.cpp`에서 센서 좌표로 칸 번호를 역산한다 (정적 배경 제거용).

```
r         = √(x² + y² + z²)
range_bin = round(r / 0.071565)
u_bin     = round((x / r) / 0.015938)
v_bin     = round((z / r) / 0.015938)
```

- cfg 키: `polar.range_res`, `polar.uv_res`
- 칸 번호는 **좌표 변환 전 센서 좌표** 기준이다. 높이 판단은 변환 후 **엘리베이터 좌표**(바닥 기준 z)를 써야 한다.
- 거리 칸 0.071565 m는 거리 해상도 c / (2 × 대역폭) 기준 약 **2.1 GHz** 대역폭에 해당한다 (4 GHz 전체를 쓰면 3.75 cm).
- 방향 칸 0.015938은 정면 기준 약 0.9°로, 각도 해상도가 3.8°라면 그보다 약 4배 촘촘하다 (방향 칸 약 4개 ≈ 해상도 1칸).

### 현재 DBSCAN (기준선)

- 이웃 판정: `√(Δx² + Δy² + (z_scale·Δz)²) ≤ epsilon` (엘리베이터 좌표)
- 파라미터: epsilon 0.30, z_scale 0.2, min_pts 10 → 수평 0.3 m, 수직 1.5 m까지 이웃
- 후보 탐색: 프레임의 모든 점과 비교 (격자 색인 없음)

## 2. 격자 칸 기준 이웃

고정 eps 대신 센서 격자 칸 번호 차이로 이웃을 판정한다.

```
이웃 ⇔ |Δrange_bin| ≤ a  AND  |Δu_bin| ≤ b  AND  |Δv_bin| ≤ c
```

### 장점

- **센서 구조 반영**: 방향 칸의 실제 폭은 멀수록 넓어지고(r × 0.0159), 거리 칸은 7.2 cm로 고정이다. 거리 비례 eps(eps = k·R)는 원 모양이라 앞뒤(거리) 방향까지 과하게 커지지만, 격자 방식은 이 문제가 없다.
- **대칭 자동 보장**: 칸 번호 차이는 p, q 어느 쪽에서 봐도 같다. 점마다 eps가 다를 때 생기는 비대칭 문제가 없다.
- **속도**: `unordered_map<(range_bin, u_bin, v_bin) → 점 목록>`으로 주변 칸만 조회하면 n × n 비교가 필요 없다.
- **이론 근거**: GDBSCAN (Sander et al., 1998, *Data Mining and Knowledge Discovery* 2:169–194). 이웃 조건이 반사적(자기 자신 포함)이고 대칭이면 DBSCAN의 클러스터 정의가 그대로 성립한다.

### 파라미터 a, b, c

- "칸 단위 eps"다. 칸이 촘촘해서 ±1~2칸은 너무 엄격하다.
- 예시: 2 m에서 옆 30 cm를 이웃으로 보려면 b ≈ 9칸 → 1 m에서는 14 cm, 3 m에서는 43 cm가 된다.
- 한 사람 데이터로 실측해서 결정한다.
- 설치 방향에 따라 키울 값이 달라진다.
  - 벽면 수평 설치: v가 대략 위아래 → c를 크게
  - 천장 설치(아래를 봄): 위아래가 주로 거리 방향 → a를 크게
  - 리허설처럼 모서리에서 숙여 단 경우(38°): v와 엘리베이터 높이 방향이 어긋나므로, 높이 규칙은 엘리베이터 좌표 z로 따로 둔다 (3장)

### 확장 (추천)

격자 조건을 기본으로 두고, 필요하면 추가 조건을 AND로 결합한다.

```
이웃 ⇔ 격자 조건 AND |Δdoppler| ≤ 임계값 AND …
```

추가 조건도 대칭이면 GDBSCAN 정의가 유지된다. AND는 조건을 엄격하게 하는 방향이라 격자 색인으로 후보를 추리는 구조도 그대로 쓸 수 있다.

### min_pts

- 경험칙: 차원 + 1 이상 (4D면 5), 노이즈가 많으면 2 × 차원
- 최종값은 k-distance 그래프와 대표 장면 시험으로 결정한다.

## 3. 직립 기준 + 낮은 덩어리 병합

**목적**: 직립 기준(수평 엄격, 수직 넉넉)으로 나누면 누운 사람이 머리·몸통·다리로 쪼개진다. 이를 후처리로 복원한다.

### 절차

1. **1단계: 직립 기준 DBSCAN**
   - 유클리드 버전: `d = √(Δx² + Δy² + (s·Δz)²)`. 예시: eps 0.3, s 0.3 → 수평 0.3 m, 수직 1 m까지 이웃. s가 모든 쌍에 같으면 z 좌표에 미리 곱해도 결과는 같다.
   - 격자 버전: 위아래 담당 축의 허용 칸 수를 크게 한다.
2. 덩어리별 **최대 높이**(엘리베이터 좌표 z_max)를 계산한다. 예시: z_max ≤ 0.6 m인 덩어리를 "낮은 덩어리"로 본다.
3. 낮은 덩어리끼리 **가장 가까운 점 사이 수평 거리 ≤ merge_gap**(예시 0.5 m)이면 Union-Find로 병합한다. 머리–몸통–다리처럼 사슬로 이어진 경우도 하나가 된다.
4. 병합 결과가 낮고(z_max ≤ 0.6 m) 길면(주성분 방향 길이 ≥ 1.0 m, 예시) `lying_candidate = true`.

### 주의

- **점 단위로 "z가 낮으면 수평 eps를 넓힌다"는 방식은 쓰지 않는다.** 서 있는 사람의 발도 낮은 점이라, 발끼리 이어져 두 사람이 합쳐진다. 덩어리 단위 판단은 이 문제를 피한다.
- 조건부로 축 비율을 바꿀 때는 좌표가 아니라 **점 쌍의 차이(Δ)**에 적용한다. 좌표에 곱하면 점 위치 자체가 이동한다.
- 1단계에서 서 있는 사람의 다리가 따로 떨어져 낮은 덩어리가 되면 오병합될 수 있다 → 1단계 수직 허용을 충분히 둔다.
- 바닥 잔여물·가방도 낮은 덩어리다 → 배경 제거 후 적용하고, 점 수가 너무 적은 덩어리는 병합에서 제외한다.
- 파이썬 참고 구현(유클리드 버전, `two_stage_dbscan.py`)은 레포에 아직 없다. C++ 포팅이 필요하다.

## 4. 붙어 선 사람 분할: 봉우리 + maybe_merged

**팀 결정**: 클러스터링(B)에서 머리 높이 봉우리로 분할하고 `maybe_merged` 플래그를 붙여 넘기면, 트래킹(C)이 시간 정보로 최종 판단한다.

### 봉우리 찾기

1. 덩어리를 수평 격자(예시 10 cm)로 나눠 칸마다 최대 z를 구해 높이 지도를 만든다.
2. 봉우리 조건 (예시): 높이 ≥ 0.9 m, 주변보다 ≥ 15 cm 솟음, 다른 봉우리와 수평 거리 ≥ 30 cm
3. 봉우리가 2개 이상이면 각 점을 수평으로 가장 가까운 봉우리에 배정한다.

### 한계

- 아이 머리가 어른 어깨보다 낮으면 봉우리가 잡히지 않는다.
- 손을 든 팔은 가짜 봉우리가 될 수 있다.

### maybe_merged 조건

| merge_reason | 뜻 | 분할 여부 |
|---|---|---|
| 0 | 정상 | - |
| 1 | 봉우리 2개 이상 | 분할함 |
| 2 | 봉우리 1개지만 폭·점 수가 한 사람치고 큼 | 분할 못 함 |

### 도플러 참고

- 둘 다 가만히 서 있으면 도플러가 모두 0이라 속도로는 구분할 수 없다. 도플러는 움직임이 다를 때만 보조로 유효하다.
- 도플러 0인 점을 지우는 필터가 있으면 서 있는 사람까지 지워진다.

## 5. B → C 출력 필드 추가 제안

현재 합의된 형식(README 참고) 위에 추가하는 제안이다.

### 모든 클러스터

| 필드 | 설명 |
|---|---|
| `frame_id`, `timestamp_us` | 프레임 정보 |
| `cluster_id`, `n_points` | 덩어리 번호, 점 수 |
| `cx, cy, cz` | 중심 |
| bbox / size | 크기 |
| `z_max` (또는 `z_top`) | 높이 |
| `mean_doppler` | 평균 속도 |
| `lying_candidate` | 누운 자세 후보 (3장) |
| `maybe_merged` | 합쳐짐 의심 (4장) |

### maybe_merged일 때 추가

| 필드 | 설명 |
|---|---|
| `merge_reason` | 0 정상, 1 봉우리 분할, 2 크기 초과 |
| `parent_id` | 분할 전 덩어리 번호. 같은 덩어리에서 나온 조각은 같은 값 → 트래킹이 잘못 나뉜 경우 재병합 가능 |
| `peaks` | 봉우리별 (x, y, z) |
| `width` | 주성분 방향 수평 길이 |
| `point_indices` | 분할 전 덩어리의 점 인덱스 (같은 프로세스면 좌표 복사 대신 인덱스) |

축 정렬 박스는 대각선으로 누운 사람을 과대평가하므로, 길이 판단은 주성분 방향으로 한다.

## 6. 결정성

- DBSCAN은 처리 순서와 무관하게 **클러스터 개수, Core 점, 노이즈가 항상 같다.** 두 클러스터의 Core 점 양쪽에 걸친 Border 점의 라벨만 순서에 따라 달라진다.
- 프레임 간 흔들림을 줄이려면 점을 항상 같은 순서(예: 칸 번호 순)로 처리한다.

## 7. 진행 순서

1. **격자 칸 기준 이웃**: 기존 C++ DBSCAN의 이웃 판정을 교체 (polar_grid 칸 번호 재사용, cfg로 기존 방식과 전환). 한 사람 / 붙어 선 두 사람 / 먼 사람 장면으로 a, b, c 실측
2. **낮은 덩어리 병합 + lying_candidate**: 누운 자세 데이터로 검증
3. **봉우리 분할 + maybe_merged + 출력 필드 확장**: 키 차이가 큰 두 사람, 쪼그려 앉기(아이 상황 모사)로 검증
4. **도플러 AND 조건** (필요 시): 속도 해상도는 교육 자료에 없으므로 센서 chirp 설정 확인 후 결정

### 검증에 쓸 리허설 장면

| 확인 | 장면 |
|---|---|
| 사람 1명이 덩어리 1개 | R1-1 ~ R1-4, R2-1 |
| 두 사람 분리 | R3-1 |
| 아이 상황 (쪼그려 앉기) | R3-2, R3-3 (미녹화) |
| 누운 자세 | R5 (미녹화) |
| 빈 장면 잔여 덩어리 | R0-2 |
